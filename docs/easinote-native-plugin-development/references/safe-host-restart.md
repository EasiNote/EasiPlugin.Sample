# 安全退出与重启 EasiNote

当插件安装、更新、卸载组件或切换关键配置后，必须重启 EasiNote 才能生效时读取本文。

本文涉及的 AppHost、命令名、注册表和内部关闭控制器来自已验证宿主版本，属于版本相关实现。接入前必须检查目标 EasiNote 版本实际提供的帮助类、命令和路径规则。

## 安全重启目标

安全重启必须同时满足：

- 退出前执行课件同步、关闭确认和其他收尾工作；
- 用户可以取消退出，取消后不启动第二个实例；
- 等待所有相关 EasiNote 进程真正退出后再启动；
- 从当前安装信息读取实际版本路径，避免启动旧版本；
- 重启等待逻辑不依赖即将退出的宿主进程；
- 连续点击不会创建多个等待器或多个新实例。

## 两个进程承担不同职责

宿主进程不能可靠地在自身完全退出后重新启动自己。安全重启应拆分为：

1. EasiNote 宿主进程执行完整安全退出；
2. 独立的 `EasiNote.AppHost.exe` 等待宿主进程全部退出，再启动实际安装版本。

推荐时序：

```text
用户发起重启
  → 验证 AppHost 和重启命令可用
  → 启动 AppHost 重启等待任务
  → 执行宿主完整退出命令
  → 同步、确认和关闭处理完成
  → Shell 与相关宿主进程退出
  → AppHost 确认目标进程全部退出
  → 读取当前 ActualExePath
  → 启动一个新实例
```

必须先成功启动等待器，再发起退出。否则宿主可能进入关闭阶段后没有任何进程负责重启。

## 复用宿主完整退出流程

已验证版本的托盘安全退出入口最终执行：

```text
ENCommands.ExitWholeApplication
```

该命令进入宿主完整关闭流程，可能包含：

- 标记应用准备退出；
- 切换 UI 线程；
- 防止重复关闭；
- 多标签窗口协调；
- 课件同步；
- 用户关闭确认；
- 其他关闭处理器；
- 完成后关闭 Shell、托盘和宿主进程。

需要与托盘退出一致的安全语义时，应调用宿主提供的完整退出命令，不要直接：

- `Application.Current.Shutdown()`；
- `Environment.Exit(...)`；
- `Process.Kill()`；
- 只关闭当前窗口或 Shell；
- 跳到内部退出核心阶段。

`ENCommands.ExitWholeApplication` 可能在宿主 UI 和托盘服务初始化后才可用。调用前确认命令已初始化，并只在宿主支持的生命周期中调用。

## 不要绕过关闭处理器

已验证版本中的内部退出核心负责真正结束进程，但它位于完整流程后半段。直接调用内部核心可能绕过：

- 未完成课件同步；
- 用户确认；
- 多标签延迟关闭；
- 后续版本新增的关闭处理器。

不要复制宿主关闭控制器内部实现。关闭规则会演进，复制代码会导致不同入口行为不一致。

## AppHost 等待器

已验证版本使用 `EasiNote.AppHost.exe` 接收跨进程重启命令。等待器通常负责：

1. 根据宿主定义的进程名检查相关进程；
2. 在限定时间内轮询等待全部退出；
3. 超时后结束，不启动新实例；
4. 从注册表或宿主安装信息读取 `ActualExePath`；
5. 使用该路径启动当前实际版本。

不要只等待发起重启的单个 `Process` 对象。EasiNote 可能采用多进程架构，必须等待宿主定义的相关进程全部退出。

使用宿主部署目录定位 AppHost，不依赖当前工作目录。处理：

- 文件不存在；
- 路径不可访问；
- `Process.Start` 失败或返回空；
- Win32 启动错误；
- 重启命令名不可用；
- 必要启动参数无法生成。

如果等待器启动失败，不应继续关闭当前应用，因为此时无法完成重启。

## 用户取消退出

安全退出允许用户因同步、确认或其他关闭条件取消操作。

正确语义：

```text
用户确认退出
  → 宿主全部退出
  → AppHost 启动最新版本

用户取消退出
  → 宿主继续运行
  → AppHost 等待超时并结束
  → 不启动新实例
```

不要在固定延迟后无条件启动可执行文件，也不要发出退出命令后立即启动新实例。否则用户取消退出时会产生重复实例。

用户取消属于正常业务分支，不应报告为“重启失败”。等待器启动失败则是需要报告的错误，两者必须区分。

## 实际版本路径

已验证版本会从安装注册表读取 `ActualExePath`，而不是复用当前进程路径。这样可处理组件更新或版本切换后当前进程仍运行旧版本的场景。

不要：

- 硬编码带版本号的安装目录；
- 使用当前工作目录；
- 默认使用当前进程可执行文件路径；
- 把开发机注册表探测结果提交到源码。

注册表键、值名和路径属于版本相关实现，应通过目标版本现有帮助类或安装信息 API 获取。

## 只在确实发生变更后提示重启

调用方维护明确的“需要重启”状态，并仅在影响运行时加载结果的操作成功后设置，例如：

- 组件安装成功；
- 更新或卸载成功；
- 关键配置切换成功且只能重启生效。

失败、取消或没有实际变化时，不提示重启。

## 防重复触发

启动等待器后，宿主仍需一段时间才能退出。重启入口应幂等防抖，避免创建多个等待器：

- 首次触发后禁用按钮或命令；
- 记录“正在重启”状态，拒绝后续调用；
- 只在等待器启动失败时恢复可操作状态。

这里的状态控制有真实的用户重复点击语义，与无依据给普通插件初始化增加 `Interlocked` 不同。

## 保留启动上下文

某些模式可能需要传递：

- 启动模式；
- 显示器标识；
- 多屏参数；
- 宿主已有的其他必要命令行参数。

优先复用宿主现有参数生成逻辑，不要在多个插件调用方分别拼接命令行。丢失参数可能使重启后进入错误模式或显示器。

命令行参数中不得包含凭据、令牌或不必要的敏感数据。

## 实现顺序

在目标项目中接入时按以下顺序：

1. 找到目标版本现有的重启帮助类、AppHost 路径和跨进程命令常量；
2. 找到与托盘退出相同的完整退出命令；
3. 检查命令初始化时机和 UI 线程要求；
4. 生成并验证 AppHost 启动参数；
5. 启动等待器，并确认启动成功；
6. 将重启入口切换为不可重复触发状态；
7. 调用完整安全退出命令；
8. 对等待器启动失败进行恢复和错误提示；
9. 不在插件进程中等待自身退出，也不直接启动新实例。

## 不推荐实现

禁止或避免：

- `Environment.Exit(...)`；
- `Process.Kill()` 或批量杀进程；
- `Application.Current.Shutdown()`；
- 只关闭当前窗口或当前 Shell；
- 调用内部退出核心绕过关闭处理器；
- 设置生命周期状态后自行结束进程；
- 在宿主进程中固定延迟后启动自身；
- 使用旧进程路径代替实际安装路径；
- 复制托盘退出内部实现；
- 用户确认退出前立即启动新实例；
- AppHost 启动失败后仍关闭当前应用；
- 连续点击创建多个等待器。

## 验证场景

至少验证：

1. **正常重启**：确认退出后所有旧进程结束，随后只启动一个实例；
2. **取消退出**：当前实例继续运行，等待器超时后没有新实例；
3. **存在待同步内容**：进入与托盘退出相同的同步流程；
4. **多 Shell 或多进程**：等待所有目标进程退出；
5. **等待器缺失或无法启动**：当前应用不先退出，并显示明确错误；
6. **连续点击**：不会启动多个等待器；
7. **版本切换**：新实例路径来自实际安装信息而不是旧进程；
8. **特殊启动模式**：多屏、指定显示器等上下文保持正确；
9. **命令未初始化**：不会崩溃或进入不可恢复的半重启状态。
